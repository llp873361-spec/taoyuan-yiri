# 桃源一日

送给她的单文件 3D 网页礼物，按《桃花源记》的结构：黎明乘小船沿桃花溪逆流而上，两岸桃林，林尽水源，穿过山洞，豁然开朗——
在一片秘境里度过一整天：清晨白银花园城堡 → 黄昏落日海 → 入夜哥特城堡 → 深夜梵高星空 → 凌晨极光雪原。
成品是一个约 300 MB 的单文件 HTML，双击就能离线打开（Chrome / Edge / Safari），发给她只发这一个文件。规格和进度见 `CLAUDE.md`。

**下载**：https://github.com/llp873361-spec/taoyuan-yiri/releases/tag/v1.0
（GitHub 附件名不能用中文：`taoyuan-yiri.html` 直接下载就能双击打开；`taoyuan-yiri.zip` 小一些，解压出来是 `桃源一日.html`。超过 GitHub 单文件 100 MB 的上限，所以不在仓库文件里。）
本地 `npm run build` 以后，根目录也会出一份 `桃源一日.html`（被 .gitignore 忽略）。

## 怎么构建

需要 Node 20 以上。

```bash
npm install
npm run build
```

构建产物在 `dist/index.html`，构建完自动复制一份到根目录的 `桃源一日.html`（两份内容一样；截图、烘焙脚本认 `dist/index.html`）。所有代码、模型、贴图、全景图、飞行视频都内联在里面，不联网。

## 怎么看

- 双击 `桃源一日.html`，点"点击开启"。插上电源效果更好；有独显的 Windows 笔记本，可以在"设置 → 系统 → 显示 → 图形"里把浏览器设成"高性能"。
- 开场（约 62 秒）是镜头自己走的：坐船沿溪、上岸、进洞；在洞里原地交给花园，出洞升起来看整个秘境，再飘到水池边。
- 地点里：WASD 走路，Shift 跑；按住鼠标左键拖动转头。停留时间到了镜头自己飞去下一个地点（她正在走就等她停下 3 秒再起飞），飞行途中也能拖动转头（±30°，松手回正）。星月夜也能走，只是圈在出生点 12 米以内（走远了就不像一幅画了）；哥特城堡左边有一座石桥通到城堡脚下。
- 空格 暂停 / 继续；← → 上一个 / 下一个地点（同色薄雾淡出淡入，飞行途中按 → 直接到目的地）；F 全屏；H 隐藏界面。
- 最后停在极光雪原，结尾文字、致谢按钮、"再走一遍"（从溪口重新开始）依次淡入。

画质自动选三档：独显和较新的核显（Iris Xe、Intel Arc 核显、Radeon 680M~890M、Apple M 系列）都走 hi，最高画质参数；
独显按 60 帧、核显按 30 帧算，显卡吃紧时先把场景分辨率降到 0.55~1 倍再用 FSR1 放大，实在不够才在下一次起飞时降到 mid；
更慢的核显走 mid（低分辨率渲染 + FSR1 放大 + 低档效果参数）；老核显或没有显卡加速走 pano（播放开发机上烘好的 360° 全景和飞行视频，叠一点实时的动态）。
浏览器连 WebGL2 都打不开时，用 CSS 3D 立方体看同一套全景和飞行视频。

地址后面可以加参数（在浏览器地址栏里文件名后面加）：

| 参数 | 作用 |
|---|---|
| `?debug` | 打开调试面板：帧率、内存、时间轴、画质、自由相机、每层效果开关 |
| `?q=hi` / `?q=mid` / `?q=pano` | 强制画质档位（强制时不动态调分辨率；`?q=hi&dynamic=1` 强制 hi 但照常动态调） |
| `?gpuSlow=7.5` | 调试用：把基准测试和每帧显卡时间都乘这个数，在独显上模拟核显，看判档和动态分辨率怎么走 |
| `?webgl=1` | 强制走 WebGL2（测兜底路径） |
| `?css=1` | 强制走 CSS 3D 全景（测最后的兜底） |
| `?world=1` | 秘境俯瞰：只看常驻远景，WASD 飞、QE 升降、Shift 加速；面板里拖时刻滑条、跳到各地点 |
| `?compilestats` | 查卡顿用：记下每一次建渲染管线（同步还是异步、哪个材质），`__gift.compileStats()` 读出来 |

参数可以组合，比如 `桃源一日.html?debug&q=mid`。

## 截图验收

用本机装的 Chrome 无头截图，断网，同时收集控制台报错和内存泄漏：

```bash
npm run shot
```

常用选项：

```bash
node scripts/shot.mjs --backend=webgpu --scene=aurora --layers
```

- `--backend=webgpu|webgl|both`：截哪个后端（默认两个都截）
- `--scene=aurora`：只截一个场景
- `--layers`：额外截逐层对比图（每个机位全开一张，再每次只关一层）
- `--query=q=mid`：给页面加参数
- `--software`：用软件渲染模拟没显卡的电脑
- `--world`：秘境俯瞰模式的截图（3 公里高空俯瞰四个时刻、正上方地图、每个地点 8 方向环视），文件名以 `world_` 开头
- `--flights`：只截飞行：每段航线在 0 / 25 / 50 / 75 / 100% 处各一张，文件名 `flight_<出发>-<到达>_<进度>.png`（不加 `--scene` 时默认也会截）

截图在 `shots/`，报告在 `shots/report.json`。有报错、外部请求或泄漏时退出码为 1。

## 全景和飞行视频（pano 档、CSS 兜底用）

画面改了以后要重新烘焙（在开发机上用本机显卡，约半小时），烘完再构建一次：

```bash
npm run build
node scripts/bake-pano.mjs
npm run build
```

- `--locations=garden,aurora`：只烘这几个地点；`--no-flights` / `--no-panoramas`：只烘一样；`--legs=garden-sunset`：只烘这几段飞行
- `--html=路径`：烘一份冻结的产物副本（烘焙期间还能继续改代码、构建）

烘焙点、视角关键帧、全景宽度、视频码率在 `src/config.js` 的 `panorama` 段。产物在 `assets/opt/pano/`（`manifest.json` 是清单）。

## 素材

两座城堡、焦点樱花树、岩石扫描和地表贴图用了 Sketchfab（CC BY）和 Poly Haven、Quaternius（CC0）的素材，声音和音乐是程序合成的。原始素材放在 `assets/raw/`（不进仓库），处理脚本：

```bash
npm run opt
```

处理结果输出到 `assets/opt/`。每个外部素材都要在 `assets/credits.json` 里登记标题、作者、许可、链接、用途，缺字段脚本会报错；登记过的会出现在结尾的致谢里。

## 可调参数

所有文字和数字都在 `src/config.js`：

- 开场卡标题、结尾文字（`endingText`，自己填）、"致谢""再走一遍"的字
- `scenes`：每个地点的停留秒数、调色（曝光、对比、饱和、色调、色调映射）、截图时间点
- `overture`：开场的船速和镜头路线、桃树和草的密度、贴水晨雾、洞里的明暗适应、崖面上的晨光（`dawnGlow`）、洞口透出的暖光（`mouthGlow`）
- `garden`：水池、花圃、柏树、花树、城堡大小、倒影分辨率、晨雾、光束
- `gothic`：城堡大小、窗灯亮起的节奏和亮度、倒影光柱长度、萤火虫、夜雾
- `starry`：天空贴图分辨率、LIC 步数、笔触数量、柏树、油画滤镜（前景的配色、笔触、勾边跟着画布一起从边缘蔓延，调试面板里是「前景笔触」开关）
- `sunset`、`aurora`：落日和雪原的各层效果
- `world`：秘境的地点坐标、一天各时刻的天色（太阳、月亮的位置）、远景的雾 / 云 / 窗灯、山洞的形状、各条溪河的走向
- `world.flight`、`world.legs`、`timeline`：飞行、航线、起飞等待、方向键跳转
- `quality`：三档的判定阈值和各档参数、动态分辨率；`post`：泛光、暗角、颗粒、画布、FSR 锐度、光束
- `perf`：2026-10-02 性能返工加的各项省算（草、树、各地点、窄处），每项都有开关，关掉就回到原来的画法
- `audio`：总音量、各地点的环境声种类和音量、轻音乐的音量和节奏
- `camera.sway`：镜头的呼吸感和走路晃动（`enabled` 改 false 整个关掉）

改完重新 `npm run build`。
